## Choose a Language

Set `language` in `plugins/FrameUI/config.yml` and run `/frameui reload`:

```yaml
language: en
```

| Code | Language | Code | Language |
| --- | --- | --- | --- |
| `en` | English | `es` | Spanish |
| `ru` | Russian | `de` | German |
| `fr` | French | `pt` | Portuguese |

Regional forms such as `en-SG`, `zh_SG`, `ms-SG` and `ta-SG` resolve to their base language. English, Mandarin, Malay and Tamil are included.

## Customize Translations

On startup, missing bundled files are copied to `plugins/FrameUI/languages/`. Edit `languages/<code>.yml` to customize that translation. Keep the existing keys and placeholders, then reload.

`messages.yml` contains chat panels, command help, hover text and resource-pack messages. Existing custom values in that file take precedence over the selected language. Unchanged bundled English values follow the selected translation.

Missing keys fall back to bundled defaults in memory. Reload does not rewrite your custom file to fill them in. Invalid language codes or malformed files reject the reload and keep the running state.

## Formatting and Placeholders

Chat messages use MiniMessage formatting and literal `{name}` placeholders. Preserve the placeholders from the message you edit; different keys receive different values. Dynamic values are inserted as literal text, so player or effect names do not become formatting tags.

Effect names and captions are author-controlled content. They do not translate automatically. Effect captions are plain text and use their own color settings; see [Effect Files](/frameui/configuration/effects/).

## Studio Language

A personal editor link opens in the accepted plugin language. The language selector in Studio can override it for that browser without changing server configuration, effect IDs, captions, images or exported YAML.

Standalone Studio defaults to English and remembers an explicit language selection. Translations are bundled with Studio; they do not require a translation service.

## Welcome Panels and Controls

Welcome text and command-help descriptions are included in all 28 language catalogs. The `welcome.*` keys cover the ready message, link labels, usage and preference headings, action labels, hover text and enabled/disabled confirmations. The `commands.help-group-welcome`, `commands.help-desc-welcome-*` and `commands.help-detail-welcome-*` keys supply the help section.

Preference confirmations use the shared `chat.separator`, a centered **Welcome Message** heading, the outcome and **Preview** plus **Enable** or **Disable** actions. Already-enabled and already-disabled responses have their own `welcome.already-shown` and `welcome.already-hidden` keys. The welcome usage heading and description reuse the styles from `commands.unknown-command-title` and `commands.unknown-command`.

The renderer supplies click targets and the welcome banner's branding colors and layout. Editing a label does not change its action. **Never show again** appears only on automatic greetings; manual previews omit it. General command-usage placeholders receive one space on each side of `|` when rendered.

Set `startup-banner: false` in `config.yml` to suppress automatic greetings, or let individual administrators use [Welcome Controls](/frameui/commands/#welcome-controls). Missing new message keys use bundled defaults without rewriting existing files.
