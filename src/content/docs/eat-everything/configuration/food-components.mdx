`food-components.yml` is where you define foods once and let the plugin apply them to every matching item on the server. Each entry under `food:` is one **component**.

<Aside type="tip">
    Prefer a visual workflow? Prototype with [`/ee` commands](/eat-everything/features/live-item-editing), run `/ee info`, then copy the numbers into this file.
</Aside>

---

## File Layout

```yaml
food:
  my-food:              # the component ID
    item: STICK         # required: the material
    components:         # everything below is optional
      nutrition: 3
      saturation: 1
      # ...
```

* **The ID** (`my-food`) is what you type in `/ee item my-food`. IDs are case-insensitive, so `My-Food` and `my-food` are the same food for `/ee item`. Do not define two IDs that differ only in case; the later one wins for that command.
* **`default`** is a documentation example. It is **never** loaded, whatever it contains.
* **Order matters.** If several entries use the same material, the first one whose [conditions](#conditions) match wins.
* Every option has a default. A missing or invalid value falls back to it, and mistakes are written to the console. See [Troubleshooting](/eat-everything/misc/troubleshooting).

---

## `item`

The material that becomes edible, for example `STICK`, `DIAMOND_SWORD` or `STONE`. Names are case-insensitive. Entries with an unknown material, or one that cannot exist as an item, are skipped with a console error. **Required.**

---

## Food Properties

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `nutrition` | whole number, 0 or more | `0` | Hunger points restored. Two points are one drumstick. |
| `saturation` | number, 0 or more | `0` | Saturation restored. Higher values keep the player full for longer. |
| `can-always-eat` | `true` / `false` | `false` | Allows eating on a full hunger bar. Enable it for potions and buffs. |

Negative numbers are raised to `0`.

## Consumption

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `eat-seconds` | number above 0 | `1.6` | How long eating takes. Values of zero or less use `1.6`. |
| `animation` | name | `EAT` | Use animation: `NONE`, `EAT`, `DRINK`, `BLOCK`, `BOW`, `SPEAR`, `CROSSBOW`, `SPYGLASS`, `TOOT_HORN` or `BRUSH`. An unknown name uses `EAT`. |
| `consume-particles` | `true` / `false` | `true` | Crumb or splash particles while eating. |
| `sound` | sound key | empty | Sound played when eating finishes, for example `entity.player.burp`. Empty keeps the material's own eating or drinking sound. An invalid key is ignored. |

The sound takes a vanilla sound event key, or the key of a sound from a resource pack, with or without the `minecraft:` prefix.

## Eating Effects

### `cooldown`

Seconds before the player can use **that material** again after eating. The hotbar shows the white cooldown overlay, and it applies to the material, not only to this component: all items of the same material share it. Whole number, `0` or more. Default `0`.

### `random-teleport-diameter`

Teleports the player to a random location within this many blocks when eating finishes, the same effect as a chorus fruit. Number above `0` enables it. Default `0`.

### `clear-all-effects`

Removes every active potion effect from the player when eating finishes, like drinking milk. Default `false`.

### `effects`

A list of potion effects applied when eating finishes. Each entry needs a **unique key**; `'1'`, `'2'`, `'3'` is the convention.

```yaml
effects:
  '1':
    name: REGENERATION
    amplifier: 1
    duration: 100
    probability: 0.5
  '2':
    name: minecraft:speed
    duration: 200
```

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `name` | potion effect | none | **Required.** Effect name, case-insensitive, with or without `minecraft:`. Unknown names skip the entry. |
| `amplifier` | whole number, 0 or more | `0` | `0` is level I, `1` is level II. |
| `duration` | ticks, 1 or more | `1` | 20 ticks are one second. Values below 1 become 1. |
| `ambient` | `true` / `false` | `false` | Styles the effect like a beacon's: translucent particles. |
| `show-particles` | `true` / `false` | `true` | Whether the effect shows particles around the player. |
| `show-icon` | `true` / `false` | `true` | Whether the effect shows an icon in the corner of the screen. |
| `probability` | number above 0, at most 1 | `1` | Chance this effect is applied each time. `1` is always. Anything else is skipped with a warning. |

Each effect rolls its probability **separately**, so three effects with `probability: 0.5` give each a half chance independently.

<Aside type="note" title="Order of consume effects">
    When eating finishes, the plugin applies the random teleport first, then clears all effects, then applies the `effects` in file order. Clearing before applying means `clear-all-effects` never removes the effects this same food grants.
</Aside>

## `permission`

The permission node a player needs to finish eating. Leave empty to allow everyone. Default empty.

A player without it cannot complete eating: the action is cancelled and nothing is consumed. **No message is sent.** The node is not defined by the plugin; choose any name and grant it with your permissions plugin.

## `conditions`

Conditions decide which items of the material this component applies to. **All present conditions must match** (logical AND). The block is optional: leaving it out makes the component apply to **every** item of that material.

```yaml
conditions:
  name: "&#FFAA00Golden Stick"
  lore:
    - "&#AAAAAAA shiny stick"
  amount: -1
  enchantments:
    - "SHARPNESS:3"
```

| Condition | How it is compared |
| --- | --- |
| `name` | The item's display name must equal the text exactly, after colors are applied. Leave it empty `""` or write `skip-check` to accept any name. |
| `lore` | The item's lore must equal these lines, in order. **An empty list `[]` means "no lore at all".** Remove the whole `lore` key to accept any lore. |
| `amount` | The stack size must equal the number. `-1` accepts any amount. |
| `enchantments` | The item must carry every listed enchantment. Write `NAME` for any level or `NAME:LEVEL` for an exact level. Extra enchantments are fine. |

<Aside type="caution" title="The sample lore line">
    The bundled example contains `lore: []`. If you copy it and keep that line, only items **without** lore are matched. Delete the line when you do not care about lore.
</Aside>

Text in `name` and `lore` uses `&#RRGGBB` hex colors. It is compared after conversion, so `"&#FFAA00Golden Stick"` matches an item named with exactly that color and text. Enchantment names are the short vanilla names in any case, for example `SHARPNESS`, `UNBREAKING` or `MENDING`.

Conditions also decide what `/ee item` gives you: the item is created with the name, lore and enchantments the conditions ask for, so it is recognized by its own component.

## `converts-to`

The item the player gets back after eating, like a bowl after soup. Leave `material` empty for nothing. The remainder replaces the eaten item in the same slot (or joins the inventory when a stack was eaten).

```yaml
converts-to:
  material: BOWL
  name: "&#FFFFFFEmpty Bowl"
  lore:
    - "&#AAAAAAWash me."
  amount: 1
  item-flags: [ HIDE_ENCHANTS ]
  enchantments:
    - "UNBREAKING:1"
  unbreakable: false
```

| Option | Default | Meaning |
| --- | --- | --- |
| `material` | empty | The leftover's material, for example `BOWL`. Empty means no leftover. An unknown name disables the leftover with a warning. |
| `name` | none | Display name. Empty keeps the material's own name. |
| `lore` | none | Lore lines. |
| `amount` | `1` | How many are returned, 1 or more. |
| `item-flags` | none | Tooltip sections to hide: `HIDE_ENCHANTS`, `HIDE_ATTRIBUTES`, `HIDE_UNBREAKABLE`, `HIDE_DESTROYS`, `HIDE_PLACED_ON`, `HIDE_ADDITIONAL_TOOLTIP`, `HIDE_DYE`, `HIDE_ARMOR_TRIM`, `HIDE_STORED_ENCHANTS`. The old `HIDE_POTION_EFFECTS` still works as an alias of `HIDE_ADDITIONAL_TOOLTIP`. Unknown flags are skipped. |
| `enchantments` | none | `NAME:LEVEL` entries, for example `SHARPNESS:3`. Both parts are required. |
| `unbreakable` | `false` | Makes the leftover unbreakable. |

## `commands`

Commands run each time a player finishes eating the item. Write them without a leading slash.

```yaml
commands:
  - "give %player% diamond 1"
  - "p:spawn"
  - "broadcast %player% ate a %material%"
```

* A command runs as the **console** by default, with full permissions.
* A command starting with `p:` runs as the **player**, with only that player's permissions.
* Placeholders are replaced before the command runs:

| Placeholder | Value |
| --- | --- |
| `%player%` | The name of the player who ate the item. |
| `%sender%` | The name of whoever runs the command: the player for `p:` commands, `CONSOLE` otherwise. |
| `%consumption_time%` | The eating time in seconds, with one decimal. |
| `%saturation%` | The saturation restored, with one decimal. |
| `%nutrition%` | The hunger points restored. |
| `%material%` | The material name in capitals, for example `STICK`. |

Placeholders come from the food and the player's **name** only. The item's display name and lore are never inserted into commands, so a renamed item cannot inject commands.

<Aside type="caution">
    Console commands are powerful. Only list commands you would be comfortable running as the server, and never put `%`-placeholders in places where the value could be interpreted as another command.
</Aside>

## Complete Example

```yaml
food:
  royal-feast:
    item: COOKED_BEEF
    components:
      nutrition: 10
      saturation: 12.8
      can-always-eat: true
      eat-seconds: 2.4
      animation: EAT
      consume-particles: true
      sound: "entity.player.burp"
      cooldown: 30
      permission: "server.royal"
      effects:
        '1':
          name: ABSORPTION
          amplifier: 1
          duration: 1200
        '2':
          name: SPEED
          duration: 600
          probability: 0.5
      conditions:
        name: "&#FFAA00Royal Feast"
        lore:
          - "&#AAAAAAFit for a king."
      converts-to:
        material: BOWL
        name: "&#FFFFFFEmpty Plate"
      commands:
        - "p:me burps loudly"
        - "eco give %player% 25"
```
