`messages.yml` contains **every** line of text the plugin sends in chat. Command answers are shown as **panels**: a separator line, a centered bold title and centered body lines. The `help` and `info` screens, the help navigation buttons and the command library's error messages are all here. Edit freely, then run `/ee reload`.

---

## How Messages Work

* **Missing keys fall back to the bundled default.** After an update you never merge new keys by hand; anything absent from your file keeps working.
* **Strings or lists.** A message may be one string or a list, one chat line per entry.
* **Empty means silent.** Set a message body to `""` and that panel is not sent.
* **Console.** The console receives each panel as one log line, `Title: body`, without colors, buttons or padding.

## Styling With MiniMessage

Messages use [MiniMessage](https://docs.advntr.dev/minimessage/format.html), the format Paper itself understands:

```yaml
reloaded: '<#B8C2D4>Configuration, messages and foods were <bold>reloaded</bold>.</#B8C2D4>'
```

* Colors are hex tags, `<#RRGGBB>text</#RRGGBB>`. Named tags such as `<red>` and formats such as `<bold>`, `<italic>` and `<newline>` work too.
* Wrap each value in **single quotes**. To write an apostrophe inside, double it (`''`).
* Placeholders are written in angle brackets, `<value>`. Keep them exactly as written; the comment above each message lists what is available.

The bundled messages use the palette `#B8C2D4` for body text, `#DCE3EE` for highlighted values, `#91D7E3` for commands, `#76F5A4` for success, `#FFD166` for notices and `#FF7777` for errors.

<Aside type="note" title="Food names use a different format">
    Item names and lore in [food-components.yml](/eat-everything/configuration/food-components) use `&#RRGGBB` hex codes, because they are compared with real item names. Only `messages.yml` uses MiniMessage.
</Aside>

## Placeholders

Values are inserted as **plain text**, never as markup. A player who names an item `<click:run_command:...>` or types a command argument full of tags cannot change how the message looks or what it does.

When [PlaceholderAPI](https://www.spigotmc.org/resources/placeholderapi.6245/) is installed, its placeholders such as `%player_name%` are resolved in messages sent to **players**. Legacy `&` and `§` color codes returned by other plugins are stripped; style messages with MiniMessage instead.

<Aside type="note">
    Eat Everything does not register placeholders of its own. PlaceholderAPI support only lets *other* plugins' placeholders appear inside its messages.
</Aside>

## Panels

### Separator, title and body

| Path | Meaning |
| --- | --- |
| `panel-separator` | The line drawn above every panel. Keep the strikethrough spaces. Set to `""` to hide it. |
| `panel-title` | The title used by panels without a title of their own. |
| `panel-titles.<name>` | The title of the panel whose body is `<name>`. |

A panel is the body message plus its title. For example the body `saturation.updated-value` takes its title from `panel-titles.saturation.updated-value`.

### Command answers

| Body | Used when | Placeholders |
| --- | --- | --- |
| `about` | `/ee` and `/ee version` | `<version>`, `<author>`, `<label>` |
| `unknown-arguments` | The sender typed arguments `/ee` does not know | `<label>`, `<arguments>` |
| `reloaded` | `/ee reload` finished | |
| `not-holding-item` | A held-item command was used with an empty hand | |
| `item.unknown` | `/ee item` got an ID that is not defined | `<id>` |
| `item.invalid-amount` | The amount is not above zero | |
| `item.received` | `/ee item` gave you items | `<amount>`, `<id>` |
| `saturation.*`, `nutrition.*`, `eat-seconds.*` | `info`, `invalid-value`, `same-value` and `updated-value` for each command | `<value>`, and `<previous>` for `updated-value` |
| `edible.*` | `info`, `same-value`, `updated-value` | `<state>`, one of the `edible.states` texts |
| `effect.*` | `usage`, `no-effect`, `removed`, `unknown`, `invalid-duration`, `invalid-amplifier`, `invalid-probability`, `added` | `<label>` for `usage`, `<effect>` for `unknown` |

### The info panel

The `info` section controls `/ee info`: the title and held-item line, one row per stat (`nutrition`, `saturation`, `can-always-eat`, `eat-seconds`, `sound`), the effect rows (`effects-empty`, `effects-total`, `effect-entry`) and the click-to-copy line with its hover text. The `effect-entry` row receives `<number>`, `<effect>`, `<duration>`, `<amplifier>` and `<probability>`.

## The Help Guide

The `help` section controls the paginated guide:

| Key | Meaning |
| --- | --- |
| `title`, `description` | The heading of every page. |
| `row` | One command per line: `<command>` is the clickable syntax and `<description>` the summary. |
| `command-row`, `detail-row` | Used instead of `row` when a command is too long for one chat line. |
| `navigation` | The footer: `<previous>`, `<page>`, `<pages>` and `<next>`. |
| `disabled-navigation` | A button that has nowhere to go. `<label>` is its text. |
| `invalid-page` | The requested page does not exist. |
| `general-title`, `general` | The `/ee help general` reference. |
| `commands.<name>` | `syntax`, `description` and `hover` for each command. |

Commands the viewer has no permission for are hidden. A command whose syntax contains `[` or `<` fills the chat box when clicked; the others run immediately. The `buttons` and `hovers` sections hold the text of the **Previous** and **Next** buttons.

## Command Library Errors

The `framework` section customises errors raised before a command runs. Each entry has a `title` and a `body`, rendered as a panel:

| Key | Shown when | Placeholders |
| --- | --- | --- |
| `permission-denied` | The sender may not use the command. | |
| `unknown-command` | The command does not exist. | |
| `invalid-syntax` | Required arguments are missing or too many were given. | `{command}`, `{syntax}` |
| `must-be-a-number` | A number was expected. | `{num}` |
| `not-allowed-on-console` | A player-only command was run from the console. | |
| `please-specify-one-of` | The value must be one of a fixed list, such as `true` or `false`. | `{valid}` |
| `error-performing-command` | The command failed unexpectedly. | |

These placeholders use **curly braces** and are filled in by the command library. Leave them as written. An empty `body` restores the library's own English message.

## Example: A Quieter Server

```yaml
reloaded: ''   # reload silently

framework:
  permission-denied:
    title: '<#FF7777><bold>No Access</bold></#FF7777>'
    body: '<#B8C2D4>That command is for staff.</#B8C2D4>'
```
