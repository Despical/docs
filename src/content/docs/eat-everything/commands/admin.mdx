Every command starts with `/eateverything` or the alias `/ee`. Commands that edit or read the **item in your main hand** can only be used by players. The rest also work from the console.

The command framework is [Aikar's Command Framework](https://github.com/aikar/commands): arguments are validated before a command runs, tab completion only suggests what you may use, and error messages come from [messages.yml](/eat-everything/configuration/messages).

| Command | Permission | Console |
| --- | --- | :---: |
| [`/ee`](#version) | none | ✔ |
| [`/ee version`](#version) | `eateverything.version` | ✔ |
| [`/ee help [general]`](#help) | `eateverything.help` | ✔ |
| [`/ee reload`](#reload) | `eateverything.reload` | ✔ |
| [`/ee item <id> [amount]`](#item) | `eateverything.item` | |
| [`/ee info`](#info) | `eateverything.info` | |
| [`/ee nutrition [value]`](#nutrition) | `eateverything.nutrition` | |
| [`/ee saturation [value]`](#saturation) | `eateverything.saturation` | |
| [`/ee eatseconds [value]`](#eatseconds) | `eateverything.eatseconds` | |
| [`/ee edible [true\|false]`](#edible) | `eateverything.edible` | |
| [`/ee effect add <effect> <duration> <amplifier> [probability]`](#effect-add) | `eateverything.effect` | |

`<angle brackets>` are required, `[square brackets]` are optional. See [Permissions](/eat-everything/commands/permissions) for how to grant them.

## General Commands

### Version

```bash
/ee
/ee version
```

Shows the running plugin version and its author. `/ee` itself needs no permission so anyone can confirm the plugin is installed; `/ee version` is the same output behind `eateverything.version`.

Typing something the plugin does not understand, such as `/ee bogus`, answers with the `unknown-arguments` panel.

---

### Help

```bash
/ee help [page]
/ee help general
```

Lists the subcommands **you** may use, six per page, with **Previous** and **Next** buttons. Players get an interactive guide: hover a command to read a detail card and click it to run it or, when it needs arguments, to put it in your chat box. The console gets the same rows without interactions.

`/ee help general` prints a plain-language reference of the food options (nutrition, saturation, effects and so on). The older spelling `--general` still works. The command rows, hover cards and the reference text come from the `help` section of `messages.yml`.

---

### Reload

```bash
/ee reload
```

Re-reads `config.yml`, `messages.yml` and `food-components.yml`, then rebuilds the loaded foods. Mistakes in `food-components.yml` are reported in the console and only the broken part is skipped, so a typo never leaves you without a working setup.

<Aside type="caution" title="What reload does not do">
    * `update-checker-enabled` and `metrics` are read at **startup** only.
    * Items that already received a component keep their old values. Test changes with a fresh item from [`/ee item`](#item). See [the update marker](/eat-everything/features/custom-food-components#the-update-marker).
</Aside>

---

### Item

```bash
/ee item <id> [amount]
```

Gives you the item described by a food component. `<id>` is the entry name under `food:` in `food-components.yml`, ignoring upper and lower case. Tab completion lists every loaded ID, and the amount suggests `1`, `16`, `32` and `64`.

The item is built from the component: it already carries the food and consumable data, the leftover item, and the name, lore and enchantments the component's `conditions` look for. This is the cleanest way to test a component.

* `amount` defaults to `1` and must be above zero.
* Large amounts are split into full stacks of the item's maximum stack size.
* Whatever does not fit in your inventory is dropped at your feet.

```bash
/ee item golden-stick
/ee item healing-soup 16
```

---

### Info

```bash
/ee info
```

Prints the food data of the item in your hand:

* Nutrition, saturation, whether it can always be eaten, and the eating time.
* The consume sound, if one is set.
* Every status effect with its position, name, duration (ticks), amplifier and probability.
* A clickable line that copies a `/give @s <item>[...]` command containing the item's full component string.

If the item is not food, you are told so. The copy line is the quickest way to move a prototype into a datapack, a shop plugin or a crate reward.

## Item Editing Commands

These commands change the item in your **main hand** immediately. Without a value they only report the current one. They affect that one stack, not the item type. For every item of a kind, use [food-components.yml](/eat-everything/configuration/food-components). See [Live Item Editing](/eat-everything/features/live-item-editing) for a workflow.

If your hand is empty, you get the `not-holding-item` panel.

### Nutrition

```bash
/ee nutrition [value]
```

Reads or sets the hunger points the item restores. Two points fill one drumstick, so `6` is three drumsticks.

* Must be a whole number above zero.
* Setting a value also makes the item **always edible**, otherwise a player with a full hunger bar could not eat it.
* Setting the value it already has answers with the `nutrition.same-value` panel.

---

### Saturation

```bash
/ee saturation [value]
```

Reads or sets how much saturation the item restores. Saturation is the hidden buffer that delays hunger loss after eating.

* Must be a number of zero or more (decimals allowed, for example `4.5`).
* Setting a value also makes the item always edible.
* A value the item already has is rejected.

---

### EatSeconds

```bash
/ee eatseconds [value]
```

Reads or sets how many seconds eating takes. Vanilla food takes `1.6`.

* Must be a number above zero, for example `0.5` for a quick snack or `5` for a feast.
* If the item has no consumable data yet, a default one is attached first.

---

### Edible

```bash
/ee edible [true|false]
```

Reads or sets whether the item can be eaten on a **full** hunger bar. Use `true` for potions, buffs and utility consumables, and `false` for ordinary food.

Only `true` and `false` are accepted; tab completion suggests both.
