## Which server software, Java and Minecraft versions are supported?

* **Server:** [Paper](https://papermc.io/) or a compatible fork. Plain Spigot is not supported because the required data component classes do not exist there.
* **Java:** 25 or newer.
* **Minecraft:** 1.21.11 and newer, tested up to 26.3.

## Does the plugin make every item edible automatically?

No. Nothing changes until you either edit an item with `/ee` commands or define a food in `food-components.yml`. Then only the items you target become food.

---

## What is the `default` entry in `food-components.yml`?

A documented example. It is never loaded. Copy it and give it a new ID.

---

## Why does my food only match items without lore?

The sample contains `lore: []`, which means "no lore". Remove the line to ignore lore, or list the lore you require.

---

## Can several foods use the same material?

Yes. Make them distinguishable with `conditions` (name, lore, amount, enchantments). When more than one matches, the **first** in the file wins, so put specific entries above broad ones.

---

## Does `/ee reload` update items players already have?

No. Items that received a component carry an update marker and keep their data. Reload rebuilds the definitions used for new items, permission checks, cooldowns and commands. Use fresh items from `/ee item` to test. See [The Update Marker](/eat-everything/features/custom-food-components#the-update-marker).

---

## Which settings need a restart?

Only `update-checker-enabled` and `metrics` in `config.yml`. Everything else applies on `/ee reload`.

---

## Why do most commands only work in game?

They read or edit the item in your main hand. `/ee`, `version`, `help` and `reload` also work from the console.

---

## Do consume commands run as the console or the player?

As the **console**. Start a command with `p:` to run it as the player.

```yaml
commands:
  - "say %player% ate a %material%"
  - "p:me feels strange"
```

Placeholders are listed in [food-components.yml](/eat-everything/configuration/food-components#commands).

---

## Can an edible item clear potion effects?

Yes. Set `clear-all-effects: true`. Effects the same food grants are applied afterwards and are kept.

---

## What does `/ee effect clear` remove?

Every consume effect on the item: potion effects, random teleport and clear-all-effects. Food values, eating time, animation and sound stay.

---

## Can eating leave something behind?

Yes. Use `converts-to` for a bowl, bottle or any customised item.

---

## Does Eat Everything add PlaceholderAPI placeholders?

No. With PlaceholderAPI installed, other plugins' placeholders work **inside Eat Everything's messages**.

---

## How are messages styled?

`messages.yml` uses [MiniMessage](https://docs.advntr.dev/minimessage/format.html), for example `<#B8C2D4>text</#B8C2D4>` for hex colors and `<bold>` for bold. Every command answer is a panel with a separator line and a centered title. Names inside `food-components.yml`, such as item names and lore, use `&#RRGGBB` hex codes. See [messages.yml](/eat-everything/configuration/messages).

---

## Does it collect data?

Anonymous usage statistics go to [bStats](https://bstats.org/plugin/bukkit/Eat%20Everything/21994): server and plugin versions, Java version and player count. Set `metrics: false` in `config.yml` or disable bStats globally in `plugins/bStats/config.yml`. The update checker contacts a public SpigotMC mirror at startup unless `update-checker-enabled` is `false`.

---

## Can players cheat by renaming an item?

If your food matches only on a name, a player can anvil-rename a matching item to receive its behavior. Add a lore line or an enchantment players cannot apply to the `conditions`, and keep powerful commands behind a `permission`.
