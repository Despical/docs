This guide takes you from an empty `plugins/` folder to an edible item you designed yourself, first with in-game commands and then as a permanent entry in `food-components.yml`.

---

## Requirements

| Requirement | Details |
| --- | --- |
| **Java** | [Java 25](https://adoptium.net/) or newer. The plugin is compiled for Java 25 and will not load on older versions. |
| **Server** | [Paper](https://papermc.io/downloads/paper) or a compatible fork. Plain Spigot is **not** supported because the plugin uses Paper's data component API. |
| **Minecraft** | 1.21.11 and newer, tested up to 26.3. |
| [**PlaceholderAPI**](https://www.spigotmc.org/resources/placeholderapi.6245/) | Optional; lets PlaceholderAPI placeholders work inside `messages.yml`. |
| **A permissions plugin** | Optional; such as [LuckPerms](https://luckperms.net/), to give staff access to individual commands. |

<Aside type="caution" title="Java 25 is required">
    If your server logs `UnsupportedClassVersionError` or "Unsupported class file major version" when loading Eat Everything, you are running an older Java. Switch the server to Java 25 and start it again.
</Aside>

## Installation

<Steps>
    1. Download the plugin from [Hub](https://hub.despical.dev/plugins/eat-everything), [SpigotMC](https://www.spigotmc.org/resources/eat-everything.116884/) or [BuiltByBit](https://builtbybit.com/resources/eat-everything.50202/).
    2. Stop the server and place `eat-everything-x.x.x.jar` in the `plugins/` folder.
    3. Start the server. The `plugins/EatEverything/` folder is created with all configuration files.
    4. Run `/ee` in game or in the console. You should see the plugin version.
</Steps>

On first start the plugin creates:

* `config.yml`: the update checker and anonymous metrics. See [config.yml](/eat-everything/configuration/config).
* `messages.yml`: all chat text. See [messages.yml](/eat-everything/configuration/messages).
* `food-components.yml`: your reusable foods, with a fully commented example. See [food-components.yml](/eat-everything/configuration/food-components).

Existing files are never overwritten by updates. A message or option added in a newer version still works with an older file because the plugin falls back to the bundled default for anything missing.

## Your First Edible Item: With Commands

Commands are the fastest way to experiment because they edit the item **in your main hand**. Give yourself an item that is normally not food, for example a stick, hold it and run:

```bash
/ee nutrition 6
/ee saturation 4
/ee eatseconds 1.2
/ee effect add regeneration 100 1
/ee info
```

<Steps>
    1. `/ee nutrition 6` restores three drumsticks of hunger and makes the stick eatable at any hunger level.
    2. `/ee saturation 4` sets how long the player stays full.
    3. `/ee eatseconds 1.2` makes eating take 1.2 seconds instead of the default 1.6.
    4. `/ee effect add regeneration 100 1` adds Regeneration II (amplifier 1) for 100 ticks, which is 5 seconds.
    5. `/ee info` prints every value and a clickable **copy** line that gives you a `/give` command recreating the exact item.
</Steps>

Hold right-click to eat the stick. It behaves like vanilla food.

![The result of /ee info on an edited item](/images/eat-everything/chat/info.png)


<Aside type="note">
    Item changes made with commands exist only on that one item stack. Players who craft, loot or receive another stick will not get the behavior. To make a *kind* of item edible for everyone, use `food-components.yml`.
</Aside>

## Your First Edible Item: With YAML

Open `plugins/EatEverything/food-components.yml` and add an entry under `food`. The entry key (`golden-stick` here) is the ID you will use in commands.

```yaml
food:
  golden-stick:
    item: STICK
    components:
      nutrition: 6
      saturation: 4
      can-always-eat: true
      eat-seconds: 1.2
      effects:
        '1':
          name: REGENERATION
          amplifier: 1
          duration: 100
          probability: 0.5
      conditions:
        name: "&#FFAA00Golden Stick"
```

<Steps>
    1. Save the file and run `/ee reload`. Warnings about mistakes appear in the console.
    2. Run `/ee item golden-stick 3` to receive three fresh sticks. They are already named **Golden Stick**, because the item command builds the item from the component and gives it the name, lore and enchantments its `conditions` ask for.
    3. Eat one. Half of the time you also get Regeneration II.
</Steps>

<Aside type="tip" title="Conditions decide which items are food">
    Because of the `name` condition, a plain stick stays a plain stick. Only sticks named **Golden Stick** are recognized, for example ones renamed in an anvil or given by `/ee item`. Remove the `conditions` block to make **every** stick edible.
</Aside>

## First-Boot Checklist

* The sample entry called `default` is **never loaded**. Copy it and give it a new ID.
* Check the console after every reload. Mistakes such as an unknown material, effect or sound are reported and only the broken part is skipped.
* Test with **fresh** items after changing a component. Items that already received a component keep their old values. See [Custom Food Components](/eat-everything/features/custom-food-components#the-update-marker).
* The sample `lore: []` condition matches only items **without** lore. Remove the line if you do not care about lore.
* Run the server on Paper. On Spigot the plugin cannot start.
