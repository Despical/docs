A **component** is a reusable food definition in `food-components.yml`. This page explains what the plugin does with it at runtime, which is useful when an item does not behave the way you expect.

---

## The Big Picture

<Steps>
    1. At startup and on `/ee reload`, the plugin reads every entry and builds an in-memory **component** for each valid one, indexed by material.
    2. While the server runs, whenever an item **appears** in a player's hands, inventory or the world, the plugin looks for a component whose material and [conditions](/eat-everything/configuration/food-components#conditions) match.
    3. If one matches and the item was not updated before, the food data is written onto the item and the item is **marked** as updated.
    4. When a player **eats** an item that matches a component, the plugin enforces the permission, starts the cooldown and runs the commands.
</Steps>

---

## Matching

For an item, the plugin looks at the components defined for its material, in file order, and uses the **first** whose conditions all pass. Conditions are parsed once when the file loads, so matching is cheap even on busy servers.

Some consequences:

* Put **specific** entries (with name, lore or enchantments) above **broad** ones for the same material.
* An entry without `conditions` matches everything of that material. Anything placed after it for the same material is never reached.
* Items are compared by their current name, lore, amount and enchantments. Renaming an item in an anvil changes which component it matches.

---

## When Components Are Applied

The plugin updates an item when it is touched, so it never scans inventories:

| Moment | What is checked |
| --- | --- |
| A player uses an item | The item used. |
| A player clicks in an inventory | The clicked item and the item on the cursor. |
| A player picks up an item | The item picked up. |
| An item appears as a dropped entity | The dropped item. |

Items inside unopened chests are updated only when someone moves them. Items made with `/ee item` are already complete.

---

## The Update Marker

After an item receives its component, the plugin stores a small marker in the item's persistent data (`eateverything:updated`). While the marker is present, the item is **not updated again**. This keeps inventory events cheap and prevents the plugin from rewriting items that another plugin or an admin edited afterwards.

The consequence is that **changing a component does not change old items**:

* `/ee reload` rebuilds the components but does not touch items that already carry the marker.
* To test a change, create a **fresh** item with `/ee item <id>`.
* To refresh items already in the wild, give players new ones or replace them with a script or another plugin.

<Aside type="note">
    The marker only controls *writing* the food data. Eating is checked against the current component every time, so a permission, cooldown or command you change in YAML takes effect on already-updated items after a reload.
</Aside>

## When an Item Is Eaten

Eating happens in this order:

<Steps>
    1. **Permission.** If the component has a `permission` and the player lacks it, eating is cancelled and nothing is consumed. No message is sent.
    2. **Cooldown.** If `cooldown` is above zero, the material's cooldown starts and the hotbar shows its overlay.
    3. **Commands.** The `commands` list runs top to bottom, as the console or, with `p:`, as the player.
    4. **Vanilla consume effects.** The game then applies the random teleport, clears effects if asked, applies the potion effects with their probabilities, and hands back the leftover item.
</Steps>

---

## Leftover Items

A `converts-to` item is written as the item's **use remainder**, the same mechanism vanilla uses for the bowl left by stew. Because the game itself handles it, leftovers stack correctly, work with every inventory type and are handled for stacks of more than one item.

## Choosing Between Components and Commands

| You want... | Use |
| --- | --- |
| To try values quickly | [Live item editing](/eat-everything/features/live-item-editing) |
| A food that exists for everyone, consistently | A component |
| Cooldowns, permissions, commands, leftovers, teleport | A component |
| A single special reward item | Either; a component if you will hand out more than one |

## Debugging a Component That Does Not Apply

1. Run `/ee reload` and read the console for warnings about that ID.
2. Hold a **fresh** item from `/ee item <id>` and run `/ee info`. If the food data is correct, the component loads fine.
3. Check the conditions. A name, lore or amount that differs from the config by even one color code or space fails. See [Troubleshooting](/eat-everything/misc/troubleshooting).
4. Look for a broader entry above yours with the same material.
5. Remember the marker: an old item keeps its old data.
