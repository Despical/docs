A **component** is a reusable food definition in `food-components.yml`. This page explains what the plugin does with it at runtime, which is useful when an item does not behave the way you expect.

---

## The Big Picture

<Steps>
    1. At startup and on `/ee reload`, the plugin reads every entry and builds an in-memory **component** for each valid one, indexed by material.
    2. While the server runs, whenever an item **appears** in a player's hands, inventory or the world, the plugin looks for a component whose material and [conditions](/eat-everything/configuration/food-components#conditions) match.
    3. If one matches and the item was not updated before, the food data is written onto the item and the item is **marked** as updated.
    4. When a player **eats** an item that matches a component, the plugin enforces the permission, starts the cooldown and runs the commands.
</Steps>

---

## Matching

For an item, the plugin looks at the components defined for its material, in file order, and uses the **first** whose conditions all pass. Conditions are parsed once when the file loads, so matching is cheap even on busy servers.

Some consequences:

* Put **specific** entries (with name, lore or enchantments) above **broad** ones for the same material.
* An entry without `conditions` matches everything of that material. Anything placed after it for the same material is never reached.
* Items are compared by their current name, lore, amount and enchantments. Renaming an item in an anvil changes which component it matches.
