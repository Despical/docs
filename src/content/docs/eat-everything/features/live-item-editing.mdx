Live editing means changing the food data of **one specific item stack** by running a command while holding it. It is the fastest way to find numbers that feel right, and the best way to learn how the pieces fit together before you write any YAML.

---

## What Gets Changed

Minecraft stores food behavior on the item itself, in two data components:

* **`food`**: nutrition, saturation, and whether the item can always be eaten.
* **`consumable`**: eating time, animation, sound, particles and the effects applied afterwards.

The `/ee` editing commands write these components straight onto the stack in your hand. The change is saved with the item: it survives dropping, trading, chests and restarts, exactly like a renamed or enchanted item.

| Command | Component | What it writes |
| --- | --- | --- |
| `/ee nutrition` | `food` | Hunger points. Also enables always-edible. |
| `/ee saturation` | `food` | Saturation. Also enables always-edible. |
| `/ee edible` | `food` | Whether the item can be eaten on a full hunger bar. |
| `/ee eatseconds` | `consumable` | Eating time in seconds. |
| `/ee effect add` | `consumable` | A potion effect with a probability. |
| `/ee effect clear` | `consumable` | Removes all consume effects. |

---

## Recommended Workflow

<Steps>
    1. Hold the item you want to experiment with.
    2. Set the values: `/ee nutrition 6`, `/ee saturation 4`, `/ee eatseconds 1.2`.
    3. Add effects: `/ee effect add regeneration 100 1`.
    4. Eat it. Adjust until it feels right, then run `/ee info` to see everything at once.
    5. Copy the numbers into a new entry in [food-components.yml](/eat-everything/configuration/food-components).
    6. Run `/ee reload` and test with `/ee item <id>`.
</Steps>

Commands show the current value when called without one, so `/ee nutrition` is also a quick way to check an item.

## Reading the Result With `/ee info`

`/ee info` is the debugging tool for live editing. It prints the final state of the item, including effects from earlier edits or from another plugin, plus a clickable **copy** line. Clicking it puts a full `/give @s <item>[...]` command on your clipboard containing the item's exact component string. You can paste that into:

* a datapack or function,
* a shop or crate plugin that accepts give commands,
* another server, to reproduce the item exactly.

## Best Use Cases

* **Balancing**: tune nutrition, saturation and eating time by trial and error.
* **One-off rewards**: hand-craft a single special item for an event.
* **Testing**: build an item that behaves like a planned food before you write YAML.
* **Staff tooling**: let trusted staff create items without editing files. See [Permissions](/eat-everything/commands/permissions).

## When Live Editing Is Not Enough

Live editing changes one stack. It cannot:

* make a *type* of item edible for everyone,
* set cooldowns, permissions, commands, leftovers or random teleport,
* survive a player crafting or looting a fresh copy of the item.

For those, define a component in [food-components.yml](/eat-everything/configuration/food-components). The two approaches combine well: prototype live, finish in YAML.

<Aside type="note">
    Items edited by command are not tied to a component. They are never touched by `/ee reload`, and the plugin's commands, cooldown and permission features only apply to items that match a configured component.
</Aside>
