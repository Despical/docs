`/port`, `/portbridge` and `/pb` share the same command tree. Console access is supported.

| Command | Permission | Effect |
| --- | --- | --- |
| `/port` or `/port status` | `portbridge.status` | Show state, target, relay, uptime, latency, retry timing and errors. |
| `/port help` | `portbridge.status` | Show available commands and clickable suggestions. |
| `/port address` or `/port ip` | `portbridge.address` | Show and copy the public Minecraft address. |
| `/port start` | `portbridge.manage` | Start preparing the tunnel in the background. |
| `/port stop` | `portbridge.manage` | Stop the tunnel and cancel pending retries. |
| `/port restart` | `portbridge.manage` | Start a replacement session; the public address may change. |
| `/port reload` | `portbridge.reload` | Validate both configuration files and reconnect an active tunnel. |

## Reload behavior

Invalid config or messages reject the reload and leave the previous settings active. A stopped tunnel stays stopped. If startup was still scheduled, reload cancels that task and reschedules it only when automatic startup remains enabled.

## Chat controls

Panels show actions according to command permissions. Copy buttons use the Minecraft client's clipboard action. Start, Stop, Restart and Refresh dispatch the same command handlers as typed commands. Console buttons include the matching command as text.

All command replies and framework permission/error replies are defined in [messages.yml](/portbridge/configuration/messages/). Diagnostic reasons can contain original I/O or Bore output.
