## Requirements

| Requirement | Supported setup |
| --- | --- |
| Server | Paper or a compatible fork, Minecraft 1.21.11 or later |
| Java | Java 25 |
| Storage | Built-in SQLite, or an existing MySQL database |
| Optional integrations | PlaceholderAPI; Vault and an economy provider for money rewards |

Folia and older Spigot installations are not supported by 3.0.0. Paper downloads the SQL drivers declared by the plugin, so allow internet access on the first startup.

## Install

1. Download the plugin from [Hub](https://hub.despical.dev/plugins/easter-eggs).
2. Stop the server and put the plugin JAR in its `plugins/` directory.
3. Start the server and check that Easter Eggs enables successfully.
4. Join as an operator or grant the relevant [administrator permissions](/easter-eggs/commands/admin/).

The plugin installs missing default files under `plugins/EasterEggs/` and preserves existing files. When updating a 2.x server, use the [migration guide](/easter-eggs/operations/) first.

## Place and collect your first egg

```text
/eggs admin
/eggs admin give easter painted-egg
```

The editor lets you choose a hunt and template. The give command selects both and gives you a placement head. Place that head where players should find it; the position becomes a tracked egg in the selected hunt.

Leave placement mode before testing collection:

```text
/eggs admin edit off
/eggs
```

Interact with the egg to collect it. Choose Easter in the player menu to see your progress, collection and rewards. For a timed hunt, run `/eggs start <hunt>` before collecting.

## Where to customize

| File | Contents |
| --- | --- |
| `config.yml` | Storage, global effect limits, inbox timing and ranking options |
| `hunts/*.yml` | Hunt rules, schedules, requirements and reward group references |
| `templates/*.yml` | Textures, rendering, particle states and default hints |
| `particle/*.yml` | Layered particle geometry and animation |
| `rewards.yml` | Reward rules, actions and weighted pools |
| `menus.yml` | Inventory layouts and labels |
| `messages.yml` | MiniMessage text, chat panels and hover descriptions |

Run `/eggs admin reload` after editing. Invalid configuration is rejected and the current running configuration stays active. Storage connection changes require a restart.
