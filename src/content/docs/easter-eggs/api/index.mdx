3.0.0 exposes `dev.despical.eastereggs.api.EasterEggsApi` through Bukkit's service manager. The 2.x static API and event classes are not the current contract.

## Dependency

Use the plugin JAR as a compile-only dependency and declare EasterEggs as a dependency in your plugin.yml:

```groovy
dependencies {
    compileOnly files('libs/easter-eggs-3.0.0.jar')
}
```

```yaml
depend: [EasterEggs]
```

Obtain the service after Easter Eggs enables:

```java
import dev.despical.eastereggs.api.EasterEggsApi;

EasterEggsApi api = getServer().getServicesManager().load(EasterEggsApi.class);
if (api == null) {
    getLogger().warning("Easter Eggs API is unavailable");
    return;
}
api.hunts().forEach(hunt -> getLogger().info(hunt.name()));
```

## Snapshots and asynchronous queries

| Method | Contract |
| --- | --- |
| hunts() | Immutable hunt metadata |
| templates() | Immutable template metadata |
| eggs(hunt) | Placement snapshots in collection order |
| cachedProgress(playerUUID, hunt) | Cached online progress, possibly absent while loading |
| preferences(playerUUID) | Cached preferences, with inherited defaults when unloaded |
| progress(playerUUID, hunt) | CompletionStage of persisted progress, including offline players |
| leaderboard(hunt, cycle, fastest, limit) | CompletionStage of ranked entries; limit 1 through 1000 |

Call snapshot methods on the server thread. Returned records and copied collections can be retained afterward. Do not block the server tick waiting for a query. Completion callbacks may run on the storage worker; return to the server thread before using Bukkit players or inventories:

```java
UUID playerId = player.getUniqueId();
api.progress(playerId, "easter").whenComplete((progress, error) -> {
    getServer().getScheduler().runTask(this, () -> {
        if (error != null) {
            getLogger().warning("Could not read Easter hunt progress");
            return;
        }
        Player current = getServer().getPlayer(playerId);
        if (current != null) {
            int found = progress.map(value -> value.found().size()).orElse(0);
            current.sendMessage("Easter discoveries: " + found);
        }
    });
});
```

The example belongs in your JavaPlugin and needs java.util.UUID and org.bukkit.entity.Player imports. Avoid retaining service references across an Easter Eggs disable/re-enable.

## Events

Events live under `dev.despical.eastereggs.api.event` in egg, hunt and reward subpackages. They use Bukkit's event system and record-style accessors such as `event.egg()`.

| Events | Use |
| --- | --- |
| EggPlaceEvent / EggPlacedEvent | Cancellable proposal / committed placement |
| EggRemoveEvent / EggRemovedEvent | Cancellable proposal / committed removal |
| EggCollectEvent / EggCollectedEvent | Cancellable discovery / committed collection |
| HuntStartEvent | Cancellable attempt start |
| ProgressChangedEvent | Committed progress snapshot |
| HuntEndedEvent / HuntFailedEvent / HuntCompletedEvent | Attempt lifecycle outcomes |
| HuntAvailabilityEvent | Availability transition |
| HuntRecordEvent | Personal or server record result |
| RewardDeliverEvent / RewardDeliveredEvent | Cancellable delivery proposal / reported delivery outcome |

Use pre-events to veto an operation and post-events to observe committed results. Cancelling a reward delivery does not undo the discovery or renew its claim.

```java
import dev.despical.eastereggs.api.event.egg.EggCollectEvent;
import org.bukkit.event.EventHandler;
import org.bukkit.event.Listener;

public final class HuntGate implements Listener {
    @EventHandler(ignoreCancelled = true)
    public void onCollect(EggCollectEvent event) {
        if (event.egg().hunt().equals("easter")
            && !event.getPlayer().hasPermission("events.spring")) {
            event.setCancelled(true);
        }
    }
}
```

Register the listener using your plugin manager. Database commits may occur after pre-events; do not treat a cancellable proposal as proof of a successful discovery.
