---
title: Required Items
description: Require and optionally consume exact materials, display names, lore, quantities, and enchantment levels.
---

Required items act as recipe ingredients in addition to the held source item.

```yaml
required-items:
  crystal:
    material: AMETHYST_SHARD
    name: "&dRefined Crystal"
    amount: 4
    lore:
      - "&7Upgrade catalyst"
    enchantments:
      - "LUCK_OF_THE_SEA:1"
no-required-items-found: "&cYou need four refined crystals."
```

## Matching Rules

- `material` must match.
- An omitted or empty `name` imposes no name restriction. Non-empty names match the complete display name after legacy color conversion.
- A non-empty `lore` list must equal the item's complete lore after legacy color conversion.
- Every configured enchantment must be present at the listed level or higher.
- Matching stacks across the main storage slots are added until `amount` is reached. Armor and offhand slots do not count.

## Removal Rules

The global `required-items.remove-on-success` and `remove-on-failure` switches independently control consumption. Removal scans the main storage slots and deducts matching stacks until the required amount is removed.

Use distinctive names or lore for valuable custom ingredients, and test stacked and split-stack inventories before publishing a recipe.

The recipe-specific `no-required-items-found` message is optional. Omitting or emptying it suppresses feedback only; missing ingredients still block the upgrade. Ingredient and balance checks run again immediately before the chance roll.

Avoid overlapping requirement entries that can match the same stacks. Each entry checks independently; use distinct ingredient metadata when different requirements must consume different items.
