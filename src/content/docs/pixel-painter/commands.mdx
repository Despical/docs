## Root Commands

`/pp` and `/pixelpainter` share the same command tree. Empty input opens help; `/pp help [page]` lists commands available to the sender's permissions. Rows suggest commands on click and show detailed explanations on hover. ## Creation and Estimates

```text
/pp create logo.png north 64
/pp create logo.png east 64 false concrete true
/pp preview logo.png 64 concrete true false
```

The second creation and the estimate use the same settings: concrete, dithering enabled and transparency disabled. The optional argument order differs between these commands.

| Option | Accepted values | Default |
| --- | --- | --- |
| Height | Positive whole number within configured limits | Required |
| Transparency | `true`, `false` | `true` |
| Palette | `all`, `concrete`, `wool`, `terracotta` | `all` |
| Dithering | `true`, `false` | `false` |

## History and Cancellation

```text
/pp history 2
/pp undo
/pp undo 012345abcdef
/pp cancel
```

Use a real ID from history. Undo access requires ownership or `pp.admin`; cancellation of another player's active world job also requires `pp.admin`. The action permission is still required. See [recovery rules](/pixel-painter/operations-and-recovery/).

## Sources and Reference

```text
/pp list 2
/pp specs portrait.jpg
/pp materials terracotta 2
/pp delete portrait.jpg
/pp reload
```

List, history, materials and help use positive one-based page numbers. An out-of-range page is rejected. Source deletion does not remove placed art or its journal.

`reload` validates settings, messages and palette before publishing them together. A failed load preserves the previous active configuration.

## Downloads

```text
/pp download portrait https://i.imgur.com/example.png
```

Replace the example URL with a real readable image. The destination must satisfy the filename policy; an absent extension becomes `.png`. Both initial and redirected hosts must be configured. See [image files and downloads](/pixel-painter/image-files/).
